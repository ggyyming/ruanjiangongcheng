# [C] 借用归还、争议与站内通知

本文可直接作为 GitHub Issue 正文。主责成员交付借用异常闭环和全站通知能力；最终合并、整体打包由本对话 Codex 负责。

## 输入与目标

先读 [共同开发约定](共同开发约定.md)、[总体分工](README_总体分工.md) 和其中 AI 开工提示词，再读 [需求规格](../需求规格说明书.md)、[细则](../附件/01_规则与数据/业务细则确认记录.md)、[状态说明](../附件/01_规则与数据/状态转换说明.md)。

主责 CP-R-03/04/14～18/26/27，协作 CP-R-07/09/10/12/21/22/25。重点 CP-D-06/07/11/12/14～16/19～22，字段和演示数据按23。

目标：从 B 的借用预留承接期限/押金约定、借用开始、归还、延期、逾期与争议，结束时符合条件才请求 B 退款；实现站内通知给 A/B/C 共同调用。不能把归还、争议关闭和资金到账合为一个状态。

## 工作清单

- [ ] C0：先提供 Loan、争议、通知最小模型/初始迁移及共同接口；Loan 关联 B 的 Transfer，不复制流转或资金表。双方期限/押金约定在借出前即可记录。
- [ ] 预留后双方确认具体归还日期时间和押金金额；修改约定须重新取得双方确认，B 交付检查引用最新双方确认版本和同一支付金额。归还时刻统一北京时间展示，数据库使用时区感知时间。
- [ ] B 借出双确认后启动借用，同一流转只启动一次；提供本人借入/借出列表、详情、约定和历史记录。
- [ ] 正常归还分别记录借用者交还、物主收回，只有一方确认不结束；双方确认且无争议才记已归还，之后请求 B 退款。退款仍处理中时页面不显示押金到账。
- [ ] 损坏争议期间记录实际交还情况，先解决并关闭争议，再允许双确认归还；不得因物品实际回到物主手中跳过争议流程。
- [ ] 延期必须在当前有效期限前申请，物主逐次批准；待批不改旧期限。允许到期后批准，但新期限须晚于批准时刻；保留原期限/申请/批准历史，多次延期均单独判断。
- [ ] `process_overdue_loans` 检查超过有效期限且未有效结束的借用，记录逾期事实、限制新增借用、通知双方，并调用 B 关闭未选中借用申请。重复执行不重复建限制或通知。
- [ ] 既有逾期限制不因跨期批准延期而清除；申请买卖/受赠、已有预留履行、已有借用归还不受本项限制阻止。
- [ ] 每次借用有效结束/争议关闭时检查用户全部相关逾期记录：逐笔已归还或赔偿结清且相关争议均关闭才自动解除本项限制。保留历史逾期，不修改身份资格或其他限制。
- [ ] 争议提交、说明/材料、协商方案、负责管理员介入记录；方案、双方履行确认、双方同意结束、系统关闭分别记录。意见不一致转管理员；管理员介入不等于绕过双方履行及结束条件自动关闭。
- [ ] 损坏赔偿另行履行，不自动扣押金；争议关闭且正常归还双确认后请求全额退押金。丢失赔偿另行履行并双方确认结清、争议关闭后记“赔偿结清”并请求全额退押金，不要求归还、不自动重新上架。
- [ ] 私密争议材料仅当事双方和负责管理员可见，包括下载路径，不能放在无需授权的公开 media URL；页面与服务端权限均测试。需要上传时明确类型/大小约束。
- [ ] 站内消息中心、仅本人查看/标记已读、关联事件/业务记录/接收人/发送与已读时间。已读不改变流转、资金或归还状态；不新增聊天或短信。
- [ ] 与 A/B 对接身份审核/撤销、物品审核/下架、预留、交付、付款/退款/结算异常、到期和逾期等通知事件；event_key 防同一事件扫描重复发送。
- [ ] 提出到期前提醒的时点/频率并交用户确定，记录未确定项；不能自称需求已经给出该参数。实现已确定的提醒规则并提供可控时间测试。
- [ ] 提交页面、测试、命令说明、通知事件清单与交接记录，协助集成者走通借还异常演示。

## 文件与依赖边界

拥有 `apps/loans/`、`apps/disputes/`、`apps/notifications/` 的模型、迁移、服务、表单、模板与测试。建议路径 `/loans/`、`/disputes/`、`/notifications/`。实现共同约定中的 C 全部服务。

调用 B 的幂等退款服务，不直接写支付成功/退款到账；受限时调用 B 关闭待选择借用申请，不改其表。归还后由 A 接受物主重上架申请，不直接写可申请。若 B0 尚未合入，先实现通知及测试设计，说明真实集成被依赖阻塞，不用自造 Transfer 替代。

## 最小验收

| 关联场景/细则 | 验收重点 |
|---|---|
| CP-SC-04 | 期限/押金双方确认、借出开始、归还双方确认、退款独立 |
| CP-SC-08 | 两笔逾期只结束一笔不恢复；全部结束仍有争议不恢复 |
| CP-SC-09、CP-D-07/19 | 申请待批不改日期、跨期批准保留限制、多次延期基准正确 |
| CP-SC-10、CP-D-12/16 | 仅有赔偿方案不结清、双方履行及结束确认后关闭、结清不等于归还 |
| CP-D-14/15 | 损坏先关争议再归还、不扣押金、实物记录与资金独立 |
| CP-D-21 | 关闭未选中借用申请，已预留/买卖/受赠保持，恢复不复活申请 |
| CP-D-20/22 | 消息仅本人、私密材料仅双方及负责管理员、已读不改变业务 |
| CP-D-06 | 到期等于边界尚未“超过”，超过后才按规则处理 |

至少保留全量恢复、多次延期、重复扫描、私密材料直接访问和双确认的数据库测试，运行本包测试及 Django check。依赖 B 的押金退款条件必须用真实服务做一次集成验证。
