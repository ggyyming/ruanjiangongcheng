# [B] 流转交易与模拟资金

本文可直接作为 GitHub Issue 正文。主责成员交付页面、逻辑、迁移、模拟服务及测试，最终交本对话 Codex 集成。

## 输入与目标

先读 [共同开发约定](共同开发约定.md)、[总体分工](README_总体分工.md) 及其中的 AI 开工提示词，再读 [本主题需求规格](../需求规格说明书.md)、[细则](../附件/01_规则与数据/业务细则确认记录.md)、[状态说明](../附件/01_规则与数据/状态转换说明.md)。

主责 CP-R-01/02/09～13/19～25，协作 CP-R-03/07/14～17/26/27。重点 CP-D-08/09/13/17/18，协作 03/04/11/15/16/21/22。

目标：复用 A 的已审核物品，让申请→预留→支付（如适用）→双确认交付→结算或借用开始能够持久化运行；取消、协商撤销、退款及资金异常也有明确可测试结果。**资金全部模拟，不接真实服务。**

## 分阶段清单

- [ ] B0：先交 Application、Transfer 最小模型、初始迁移和服务签名，固化当事人、类型、金额、预留时间和独立确认记录。依赖 A 的真实模型，不复制 User/Item；向 A 提供进行中流转和当事人查询接口。
- [ ] B1：先走通赠送：多申请人、物主选一人、唯一预留、关闭其他申请、双方交付确认。自己申请自己物品、无资格者申请、非物主选择、并发重复选择必须拒绝。
- [ ] B2：复用同一申请/交付模型支持出售、借用。买卖付款成功后才能确认交付；借用须 C 的期限和押金双方约定确认且押金付清才允许借出。赠送不产生支付、押金和付款超时。
- [ ] PaymentOperation 区分货款/押金、支付/结算/退款、业务标识、金额、状态、模拟回执、首次及重试次数和时间；界面分别显示实物流程与资金状态。
- [ ] 模拟付款可展示待支付→处理中→成功/失败/未知；回执须匹配用途、交易号、金额、状态，重复回执不重复处理。普通用户点击“已付款”不能直接写成功。
- [ ] 出售双方确认交付后才发起结算，处理中不显示卖家到账；协商撤销/争议期间暂停新结算及重试，已发请求的实际回执照实记录。
- [ ] 双方均未确认交付时任一当事人可取消，必须记原因。已关闭的其他申请不恢复；物品是否重新可申请由 A 的展示资格判断，不能把已下架内容强行公开。
- [ ] 已有交付确认不得单方取消；实现协商撤销、双方同意、双方确认未交出或已退回、生效后下架及符合条件后的退款。撤销退回不能替代 C 的正常归还记录。
- [ ] 撤销协商中暂停新增交付确认与发起结算；双方撤回撤销请求后恢复原流程和既有确认，不能清除付款或交付历史。
- [ ] 已支付且有效取消/撤销、无未解决争议时全额原路退款；正常归还或丢失结清的押金退款读取 C 的真实条件。服务内复核业务资格，不能因调用者传入 `reason` 就直接退。
- [ ] 退款/结算失败先对账，确认未成功且可重试才最多自动重试3次（不含首次）；未知先查询，不盲目重复，仍失败交负责管理员并通知双方。使用同一业务标识防重复处理。
- [ ] 实现 `process_payment_timeouts`：预留生效24小时后先核对付款，确认未付才取消；未知不能直接取消。取消后迟到成功支付不恢复订单，符合规则时进入退款。
- [ ] 实现 `process_payment_operations` 扫描对账和重试；命令重复执行不重复到账/退款。提供确定性模拟成功、失败、未知及后续查询的演示方式。
- [ ] 按 C 的限制事件关闭未被选中的借用申请，不影响买卖/受赠及已预留；通知通过 C 的幂等通知服务生成。
- [ ] 提交本包页面、测试、管理命令说明和交接记录，完成真实跨包联调。

## 文件和接口边界

拥有 `apps/transfers/`、`apps/payments/` 及各自迁移、模板、测试、管理命令。建议路径 `/transfers/`、`/payments/`。不改 A 的认证或内容审核模型，不实现 C 的延期/归还/争议关闭算法。

实现 [共同接口表](共同开发约定.md) 中 B 的全部接口。读取 A 的校内/展示资格和 C 的借用限制、交付就绪、未关闭争议；借出完成调用 C 的 `start_loan`。取消、归还/赔偿与退款触发保持独立记录。模拟工具需要受控权限；禁止以公开的“模拟回调地址”让任意用户写入资金状态。

## 必须留下的可运行检查

| 关联场景/细则 | 验收重点 |
|---|---|
| CP-SC-01、03、04 | 买卖/赠送/借出三种门槛不同，单方确认不完成 |
| CP-SC-05、06 | 取消退款分开，已下架不自动公开，其他申请不复活 |
| CP-SC-07、CP-D-13 | 单方确认后不能单方取消；协商及撤回恢复原记录 |
| CP-SC-11、CP-D-09/18 | 处理中/未知/失败不当成功，3次重试上限、暂停和转人工 |
| CP-D-17 | 24小时边界、未知查询、确认未付才取消、迟到支付退款 |
| CP-D-15/16 | 损坏不扣押金，丢失结清可退款但不写已归还 |
| CP-Q-01/02/03 | 非当事人、篡改金额、重复回执、重复预留不推进状态 |

用可控时间和模拟回执测试，不实际等待24小时、不打外网。至少保留一次两个申请争抢同一物品的数据库一致性检查；SQLite 场景不能仅依赖 `select_for_update`。交接时运行本包测试、Django check，并报告哪些跨包场景已经实际联调。
