# S1 教学班、入班和分组

采用独立 Django 单体、服务端模板、会话登录和 SQLite 作为本机实现方案，依据已确认的本机演示范围。教师账号、学生账号和角色从虚构种子数据开始。教师创建班级时成为主审，可以在本班创建小组。学生凭班级共用的随机邀请码入班，再由教师分组。

| 数据 | 约束 |
| --- | --- |
| 教学班 | 课程、学期和班级标识组成唯一身份。邀请码独立随机生成并唯一。 |
| 小组与班级成员 | 组名在班内唯一。学生在同一个班只有一条成员记录，小组可为空。服务端拒绝把成员放进其他班的组。 |
| 已提交作品 | 每组最多一条作品记录。S1 用预置作品测试读取和锁组。S2 通过有效上传在同一事务中创建首份作品及其初始版本。 |

| 验收项 | 预期 |
| --- | --- |
| 教师建班与创建小组 | 生成可供学生使用的邀请码，创建的小组出现在教师总览。其他班教师不能查看该班或修改分组。 |
| 学生入班 | 有效码加入对应班并显示待分组。重复提交保持一条成员记录。错误码不写入成员记录，学生不能创建教学班。 |
| 教师分组 | 本班学生可以进入本班组。跨班学生或目标组被拒绝。同一学生始终只有一个当前组。 |
| 作品隔离 | 负责教师和本组学生可读。同班其他组、未分组学生和跨班教师均被拒绝。 |
| 锁组 | 用已有作品验证组员不能迁出，其他学生不能加入，失败时原分组保留。S2 增测上传触发锁组。 |

后续阶段接入上传、审查与复核。工程控制台在对应业务入口可用后单独实现和验收。

2026-11-12 使用本机 Python 3.13.15、Django 5.2.17 和 SQLite 验证。6 项 Django 测试通过，覆盖实际 HTTP 登录、建班、入班、分组、作品权限、锁组和 CSRF。Django 系统检查、迁移一致性、Ruff 检查与格式检查均通过。空 SQLite 数据库迁移成功，两次执行演示账号初始化后均保有同一套四个账号。
