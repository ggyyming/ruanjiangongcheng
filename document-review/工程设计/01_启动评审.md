# 01 启动评审与分阶段验收

日期：2026-11-12。状态为 S1 已实现，等待本机人工走查。实现和自动验证记录见 [S1 实现与验收](03_S1实现与验收.md)。

## 需求基线来源与首版范围

以[需求规格说明书](../docs/需求规格说明书.md)的 DR-R、DR-BR、DR-Q 编号和[追踪矩阵](../docs/附件/需求追踪矩阵.md)为依据。本轮以本文记录的阶段决定补充该规格。早期实施方案中的 DOCX、PDF、多模板、多模型、报告导出和团队工时属于历史建议，不计入本轮首版验收。

首版主流程从教师建班开始。系统为教学班生成随机邀请码，学生登录后凭邀请码入班，教师再给本班学生分组。学生提交本组 Markdown/TXT 文档后，系统保存独立版本、锁定分组并自动开始规则审查。教师从教学班总览逐条复核，学生可提交修订版并触发新一轮审查，教师复审后记录原问题是否解决。总览包括未提交小组。章节缺项候选引用 TPL-COURSE-01 v0.1 的模板项，其余候选引用对应版本的原文行号。

## 需求1补充决定

2026-11-12 用户确认以下业务规则，补充 v0.3 需求报告。

| 编号 | 已确认的行为 | 关联需求与首版验收 |
| --- | --- | --- |
| Q-04a 教师分组 | 教师登录后可在页面给所负责教学班的学生分组。 | DR-R-09/12/13/14、DR-BR-08/09、DR-Q-01。负责教师分组成功后，学生可以访问所分配组的作品。同班其他组学生不能读取该作品，其他班教师不能修改该分组。 |
| Q-04b 教学组织 | 每班一名主审教师。学生在同一教学班最多一组。每组本次任务一份逻辑作品，修订通过增加版本完成。 | DR-R-11/13、DR-BR-07/09。验证同班重复分组和同组第二份逻辑作品被拒绝，并验证同一作品可保留多个版本。 |
| Q-04c 建班和入班 | 教师可在页面创建教学班并成为该班主审教师。系统生成随机邀请码，学生登录后凭码加入对应教学班，进入待分组名单。 | DR-R-09/12/13/14、DR-Q-01。验证有效码只关联对应班，错误码不产生班级成员记录，重复入班不产生第二条记录。 |
| Q-04d 提交后锁组 | 小组首次成功提交作品后固定成员名单。原成员不能迁出，其他学生不能加入。规则审查失败时，已提交版本及锁组状态保留。 | DR-R-11/12/13、DR-Q-01/03/04。验证提交前可调整分组，提交后拒绝迁出、拒绝未分组学生加入，并保留原成员名单。无效上传不触发锁定。 |
| Q-07 自动开始审查 | 首版和修订版均在上传成功后自动开始对应版本的规则审查。 | DR-R-01/10/11、DR-UC-02/04、DR-ST-01/02/09、DR-Q-04。成功上传后无需再次点击。格式或权限校验失败不启动审查。规则执行失败时保留已上传版本并显示失败状态。 |
| Q-08 工程控制台 | 后续提供测试控制台。测试人员可创建学生账号、直接将学生加入班级和分组，并以目标账号的身份操作其有权使用的业务功能。 | DR-Q-01、DR-R-09/12/13。验证账号创建、入班、分组、学生提交和教师复核。代操作按目标账号的权限校验，并可追溯真实操作人。 |

| 阶段 | 产出与需求追踪 | 退出条件 |
| --- | --- | --- |
| S0 需求与架构评审 | 本文、[架构讨论稿](02_架构与环境约束讨论稿.md)、现有模型和追踪矩阵 | 明确分组写入条件、越权测试和 S1 架构。 |
| S1 工程底座、授权与班级总览 | 独立可运行工程、教师建班、学生凭码入班、教师分组和班级总览。关联 DR-R-09/12/13/14、DR-Q-01。 | 用两个教学班验证建班、凭码入班、无效码、重复入班、正常分组和跨班拒绝。独立环境可运行，迁移可复现。 |
| S2 上传、版本与定位 | Markdown/TXT 文件、不可覆盖版本、行号和提交后锁组。关联 DR-R-10/11、DR-Q-01/02/03/04。 | 两次提交能分别回读原文与行号。首个有效版本提交后，锁组同时拒绝迁出和加入。无效输入保持原版本和锁组状态。跨组和跨班访问被拒绝。 |

工程控制台作为后续测试任务单独验收。在课堂账号、班组和对应业务功能可用后，分别测试直接配置数据和代目标账号操作。测试包括已锁小组的加入与迁出均被拒绝、退出代操作后恢复身份，以及对真实操作者和目标账号的追溯。
